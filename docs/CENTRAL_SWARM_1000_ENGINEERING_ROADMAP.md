# ⚔️ Thousand-Engineer Doctrine

**North star:** AoE2WAR grows into a distributed engineering organization able to coordinate and independently verify work from up to 1,000 bounded engineering agents. The aim is **verified deployed value** and a more capable kingdom—not merely more tabs, contributions, commits, diagrams or unreviewed output.

**Hard precedence:** frozen W1 production release is P0. This roadmap is isolated post-W1 source, not permission to deploy, modify money, change original visual editions or bypass B/C/D/E/F/G acceptance. Use Central #984 for priorities and #934 for release evidence. Each human owner approval and every original financial/security recovery boundary remains intact.

## 2. A six-plane distributed engineering organization

| Plane | Contract | Cannot do |
| --- | --- | --- |
| Queue and governance | Durable typed issues, dependencies, priority, owner, deadline, risk, acceptance, budget and pinned Git source | GitHub dispatch comments do not wake browser tabs |
| Worker orchestration | Future isolated workers with authenticated claim, short TTL lease, fencing token, heartbeat, retry/idempotency and cancellation | No unauthenticated or self-reported active workers |
| Source/build validation | Per-task isolated workspace, exact tree/lockfile provenance, bounded CI, browser and adversarial verification | Source-green cannot certify a host or money |
| Independent review | Distinct credential/identity and reviewer role, owner approvals, anti-replay and protected finance/security checks | Producer cannot certify its own output |
| Release and rollback | F-only protected exact-source W1 owner approvals, original FD200 lock continuity, stage/activate/postflight/rollback and separate funded Wolo approval | No unreviewed .next swap, broad root access or autonomous funded operations |
| Observation and history | Low-impact scheduled collectors, signed native receipts, immutable history, source-bound read model, public-safe projection | No SSH, scan, financial mutation or credential exposure on public request |

Task lifecycle is **ASSIGNED → ELIGIBLE → LEASED → SOURCE_RETURNED → INDEPENDENT_REVIEWED → EXACT_HEAD_CI_PASSED → MERGED → NATIVE_ACCEPTED → LIVE_VERIFIED**; not every task needs every gate, but never collapse gates into one progress bar. Each event has producer, exact SHA, schema version, observed time, evidence digest, reviewer identity and status. UNKNOWN, HOLD, STALE and NOT_APPLICABLE are distinct states; missing evidence is not success, zero, a live daemon or a healthy site.

A single owner remains the privileged deployment/deletion/spending/financial authority. Agents have least-privilege sandbox capabilities and explicit risk classes. No arbitrary shell, public token leak, financial signer or direct production DB write through task-dispatch APIs.

## 3. Capacity ladder toward 1,000

| Stage | Capacity ceiling | Graduation requirement |
| --- | ---: | --- |
| S0 — manual command | 6 allocated lanes | Owner-relayed tabs, registered work boundaries, source-linked handoffs; six is an allocation, not benchmarked automated capacity |
| S1 — governed queue | 12 | Stable typed DAG, no double claim, independent reviewer assignments; 30 real task lifecycles with exact provenance |
| S2 — automated controlled workers | 24 | Authentic worker identities/leases/heartbeats, cancellation, idempotency, bounded isolated runners; 100 fault-tested jobs |
| S3 — specialist cells | 100 | Reviewer capacity, source ownership partition, hierarchical coordinators, distributed tracing; 1,000 adverse trial jobs |
| S4 — regional departments | 250 | Federated scheduler, cost/throughput budgets, backpressure, operations and failure drill, canonical host recovery |
| S5 — distributed engineering army | 1,000 | Controlled load-test evidence for concurrency, reviewer throughput, rollback, failure containment, provenance and sustainable cost |

Every promotion requires a real evidence-certified **observed peak active worker count**, sustainable concurrency, runner cost, review capacity, isolation, stale/replay/incident trials, downstream production acceptance and independent sign-off. Any P0 in a security-critical path or missing trust authority HOLDs promotion. Theoretical scale is not certified throughput.

**Three separate fleet measures:** allocated_slots (user-assigned; six today); observed_active_workers (valid leases+native heartbeats only; currently unknown); certified_concurrent_capacity (independent load-test bound; currently unknown). The public 6/1000 aspirational progress bar must explicitly say **allocated**.

## 4. Three ratings, all versioned and evidence-bound

### A. Swarm Maturity Index — /1000, NOT headcount

A 1,000-point assessed infrastructure rubric. Points only through independently reviewed criteria with exact evidence, signed source, measurement coverage, version, freshness and explicit reviewer:

| Criterion group | Weight |
| --- | ---: |
| Queue contracts, ownership and dependency accuracy | 120 |
| Authenticated worker lifecycle and lease fencing | 140 |
| Reproducible source/CI/artifact provenance | 140 |
| Independent review, security and finance boundaries | 160 |
| Source integration, controlled release and rollback | 150 |
| Native observability, history and freshness | 110 |
| Scalability, throughput and resource cost | 90 |
| Incident handling, recovery and storage integrity | 90 |
| **Total** | **1000** |

Until enough criteria are independently assessed to publish a qualified score, show **—/1000, UNMEASURED** with coverage and the next missing evidence, not a fabricated rating. Scoring cannot conceal an unclosed hard safety gate behind other high-weight criteria.

### B. Kingdom Perfection Index — /100

Do NOT overwrite existing 20-criterion Renaissance per-route score verification. Derive the **route-quality aggregate** only from independently certified criteria matched to the actually deployed source and BUILD_ID; show evaluated-route coverage and critical specialty-gate status. A separate broader **Kingdom Health & Craft** system score may use these pillars after true instrumentation:

- 25 correctness/security and hard domain boundaries;
- 20 reliability, restore, release and tested rollback;
- 15 performance using actual controlled production cohorts (LCP/INP/CLS, API p95, error budget);
- 15 UX/accessibility with mobile/keyboard/axe authenticated acceptance;
- 15 maintainability/modularity using source-graph cycles, coupling, change impact, safe boundaries;
- 10 qualified testing, data quality, observable runbooks and true freshness.

100/100 means **all specified checks passed for a versioned, dated source/runtime snapshot**, not timeless objective perfection. If the live source or mandatory category evidence is unknown, the overall score must be **null** and public UI must say NOT VERIFIED. October 15 subjective 74/100, 88/88 navigation tests and unverified GitHub contribution count are NOT this score.

### C. Central Load / Coordination Pressure — /100

An operational pressure meter, NOT an AI emotional state claim. Measure stale handoffs, reviewer queue age, idle blocked W1 dependencies, file ownership conflicts, percent of tasks with independent source-return evidence, manual copy-paste time, p95 task cycle time and active job utilization. Publish component definitions and cohort-size/confidence, otherwise UNMEASURED. Rising pressure triggers fewer simultaneous conflicting edits, smaller reviewable patches and stronger reviewer staffing, not indiscriminate agent multiplication.

## 7. Storage doctrine is permanent

**Old Intel Mac is the designated default destination.** Previously observed about 317 GiB ordinary free and 60 GiB initial protected reserve. This is **finite storage**, not an infinite promise: every transfer remeasures source/destination bytes, CPU, network, disk health and available headroom.

E VPSSentry #61 owns source-encrypted age → pinned SSH → exact forced-command Intel receiver → copied ciphertext reread → *independent offline decrypt/restore* → immutable receipt → explicit owner exact-path consent for removal → actual measured free-space delta. D #62's incompatible sender remains disabled. Never treat copied bytes as restored or physically reclaimed. Never blindly delete old Codex worktrees, unpublished work, Traffic SQLite/WAL, Postgres, Wolo state, keys, active swap or rollback. HEL1 six-class restores are **separate** from M1 archival. No Backblaze B2 or paid Hetzner growth without new explicit owner decision.

Storage observatory must separately graph potential cargo, actually shipped ciphertext, independently restored content, verified reclaimed bytes, remaining Intel capacity and original disk risk; missing receipts are UNKNOWN.

## 9. Weekly Central review loop

Every seven days publish a compact source-linked report to the Central evidence ledger: **allocated / observed active / independently certified workers, swarm stage, maturity score or UNKNOWN, perfection score or UNKNOWN, coordination-pressure score or UNKNOWN, 7-day merges and live deployments, change failure/recovery, oldest critical HOLD, code-cycle/refactor trend, actual Intel restored/reclaimed bytes, and next promotion blocker**.
