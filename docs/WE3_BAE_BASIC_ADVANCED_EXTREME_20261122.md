# Storage OS BAE — Basic / Advanced / Extreme

Source-reviewed WE3 presentation contract, November 22, 2026. **BAE means
Basic, Advanced, Extreme**. A is **never** named Atlas. The existing unrelated
Navigation Atlas and historical Storage Atlas source contracts remain separate
systems and must not be renamed as a side effect.

## B · Basic — preserved original Explorer

The default is the existing owner-only Storage Explorer, with its original
four selectable storage surfaces, radial gross category map, ranked categories,
classification controls and exact authorization boundaries. It already includes
M1, HEL1 root, HEL1 mounted data volume, and the independent Intel vault.
There must be exactly **one** Intel tile. The new top-right B/A/E preference is
stored locally after hydration, falls back to B when storage is unavailable,
and does not cause account writes or create a new observation.

HEL1 source v1 presently emits signed empty hog lists on both the root filesystem
and mounted data filesystem; it has **not** conducted a bounded directory
allocation census. In this case the UI must say **NOT SCANNED FOR HOGS** and
report signed category count 0 while withholding total hog-allocation and
reclaimable bytes as UNKNOWN. Zero signed categories is not proof an ext4
filesystem is empty. Only a new independently source-admitted bounded native
census from WE2/WE4 may supply actual category sizes, provenance and coverage.

## A · Advanced — host relationship intelligence

Three physical computers (M1 development Mac, HEL1 production server, Intel
cold-storage Mac), four separately identified storage surfaces (HEL1 has TWO
separate filesystems), five existing Transport OS lane definitions. The expanded
three-host relation layout lets the owner inspect either HEL1 filesystem,
select a named transport relationship, see source and destination classes,
controller, hold reason and all seven independent evidence gates, and return
to Basic for real classification. This is not a copy of Basic's disk card grid.

## E · Extreme — near-full-viewport spatial command deck

Extreme widens to the browser viewport and shows a visually prominent Intel
encrypted destination, two distinct HEL1 mount nodes inside the same physical
server, static blocked lane traces, a current-observation strip and a dated
time scrubber of independently admitted source observations and Intel archive
or restore history. **No transition animation runs without authenticated
current activity.** A historical restore is not a current copy, authorization
or retirement permit. All interaction is keyboard-accessible and respects
reduced-motion preferences.

## Evidence and admission boundaries shared by B, A and E

- Server-HMAC gross categories are not a fresh source-HMAC read verification,
  a full-directory census, certified capacity, a durable Bridge ACK, measured
  physically recovered bytes or item-specific deletion authority.
- Certified capacity may be shown only where independently qualified, clearly
  distinguished from unsigned estate snapshots and category totals.
- Source statuses PASS / HOLD / STALE / UNKNOWN / NOT ADMITTED refer only to
  their admitted evidence class, not to overall machine health.
- Five named transport lanes and their seven gates remain NOT ADMITTED without
  each original controller's verified, durable per-object source/receiver
  proofs. Connections are relationships, not proof of actual file movement.
- The independently signed Intel cold-vault observation is not a fourth M1
  source-HMAC Bridge plane, and historical Intel restores do not authorize
  retirement of their originals.
- Source v1 must not be silently repackaged as native V2, or gross overlapping
  allocation misrepresented as unique filesystem free-space increase.
- No new backend, daemon, authentication platform, scan-from-browser, transfer
  executor or destructive control is authorized by this presentation change.
