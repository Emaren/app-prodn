  UTF8("aoe2war/storage-atlas/receipt-v1") || 0x00; signature 64 bytes.

  mountpoint, full 40-hex source_sha, minimum_sequence, previous_receipt_sha256.

B. DURABLE RECEIPT DIGEST AND HIGH WATER — proposed, not implemented
- Freeze proposed digest: SHA256 of EXACT BYTES
  UTF8("aoe2war/storage-atlas/receipt-v1") || 0x00 ||
  signed_payload_bytes || 64-byte_ed25519_signature, lower-case hex.
  #945 only compares external previous_receipt_sha256 to external pinned

  signed fixtures/test vectors must qualify the algorithm before activation.
- One append-only durable journal tracks per-plane key epoch, strict

- Initial sequence 1 with predecessor 64 zeros ONLY on an independently
  approved genesis enrollment. Never reset sequence on key rotation.
  Revoke old keys out of band. Require authorized operator/reviewer evidence

  journal digest, source/UUID/mount/collector must match pins, signature

- Source #945 requires measured_reclaimed_bytes NULL or missing; avoid

C. ATOMIC PUBLISHER — to be implemented in a distinct reviewed change
- A dedicated nonweb service account receives only approved host-local
  signed receipts through bounded operator-only ingress, with no public
  listener, remote command execution, cleanup or finance permissions.
- Under an exclusive publisher lock, read independent high-water and
  three immutable trust pins; verify three signatures, source/device/time,
  sequence and coverage; commit full original bytes + new journal high
  water as one durable transaction (for example SQLite synchronous=FULL).
- Materialize that committed generation to a non-web-served private dir:
  O_EXCL new file, fsync file, atomic rename on same filesystem, fsync
  directory. File cannot be symlink or hard-linked; reject writable
  ancestors and all public asset roots. On power loss reconcile from
  committed durable journal, not from a user-provided envelope.
- IMPORTANT CURRENT LIMIT: #945 Next server reads pins from STATIC
  process.env STORAGE_ATLAS_COLLECTOR_TRUST_JSON but reads bundle bytes
  per request. A changing bundle + static pins are NOT a coherently
  atomic live stream, and updating separate files under a lock alone
  cannot fix this. A separately reviewed coherent-generation reader
  OR a single explicitly approved immutable one-generation deployment
  with pins/bundle stage+restart must exist before any live opt-in.
  Restarting the website every 300 seconds is NOT an acceptable default.
- On lock contention, interrupted journal commit, lost signer, stale
  consumer pins, crash during rename, missing volume, clock dispute or
  malformed candidate: fail closed, keep previous evidence HISTORICAL,
  show UNKNOWN/HOLD and NEVER fail website deployment or block Index.
- Test hot-path read cost/maximums and avoid unlimited polling. No
  public request may trigger statvfs, diskutil, findmnt, shell, remote
  SSH, financial reconciliation, privileged signing or telemetry write.
